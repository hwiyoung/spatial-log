# SAMS 시스템 구조 설계서

## 1. 시스템 개요

### 시스템명
Spatial Asset Management System (SAMS)

### 핵심 가치
모든 프로젝트 산출물(공간+비공간)을 하나의 시스템에서 안전하게 보관하고, 누구나 검색으로 찾을 수 있게 한다.

### 사용자
사내 전용. 같은 회사 소속 4가지 역할.

### 접근 정책
현 단계(사내 전용)에서는 **모든 사용자가 모든 기능에 접근 가능**하다. 역할 구분은 권한 제어가 아니라, 화면 설계의 우선순위를 정하기 위한 것이다. "주 사용자"는 "이 화면을 설계할 때 가장 먼저 고려하는 역할"을 의미한다. 향후 클라이언트에게 시스템을 열 때 역할 기반 권한 분리를 도입할 수 있으며, 현재의 역할 정의가 그 기반이 된다.

---

## 2. 사용자 역할 정의

| 역할 | 약칭 | 핵심 동기 | 시스템 사용 빈도 |
|------|------|----------|----------------|
| 현장 담당자 | Acquirer | 취득 데이터를 빠르게 시스템에 넣고 싶다 | 프로젝트 완료 시 집중 사용 |
| 후처리 담당자 | Processor | 원본을 찾아 가공하고, 결과를 원본과 연결해 등록하고 싶다 | 프로젝트 진행 중 지속 사용 |
| PM | Manager | 산출물 현황을 파악하고, 과거 데이터를 참고하고 싶다 | 상시 사용 |
| 미래의 검색자 | Searcher | 과거 데이터를 맥락 정보 없이 찾아야 한다 | 불시 사용 (가장 중요한 역할) |

## 3. 화면 구조 (4페이지)

### 전체 레이아웃

```
┌─────────────────────────────────────────────────┐
│  상단 네비게이션 바                                │
│  [Explorer]  [Project]  [Upload]  [사용자메뉴]      │
├─────────────────────────────────────────────────┤
│                                                 │
│              각 페이지 콘텐츠 영역                  │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 페이지 1: Explorer (탐색/검색)

**목적**: 데이터를 찾는다. 시스템의 홈이자 가장 많이 쓰는 화면.

**주 사용자**: Searcher (1순위), Manager (2순위), Processor (3순위)

**구성**:
```
┌──────────────────────────────────────────────────────┐
│ Explorer                                              │
├────────────┬─────────────────────────────────────────┤
│            │                                         │
│  검색 필터  │              2D 지도                     │
│  패널      │         (데이터 위치 시각화)               │
│            │                                         │
│ ┌────────┐ │                                         │
│ │키워드   │ │    [●] 포인트클라우드                     │
│ │검색     │ │    [△] 3D모델                           │
│ └────────┘ │    [▤] 문서    ← 문서도 지도에 마커       │
│            │                                         │
│ ┌────────┐ ├─────────────────────────────────────────┤
│ │유형 필터│ │                                         │
│ │시간 범위│ │         검색 결과 목록                    │
│ │좌표계   │ │  ┌─────────────────────────────────┐    │
│ │사이트   │ │  │ ⦿ 다보탑 LiDAR 스캔              │    │
│ │프로젝트 │ │  │   2024-03-12 · 15M pts · 2.1GB  │    │
│ └────────┘ │  ├─────────────────────────────────┤    │
│            │  │ △ 다보탑 포토그래메트리 모델        │    │
│ ┌────────┐ │  │   2024-03-15 · 1.2M vertex       │    │
│ │속성 필터│ │  ├─────────────────────────────────┤    │
│ │(고급)  │ │  │ ▤ 정밀실측 보고서                 │    │
│ └────────┘ │  │   2024-04-15 · PDF · 156쪽       │    │
│            │  └─────────────────────────────────┘    │
└────────────┴─────────────────────────────────────────┘
```

**검색 방식**:
- 키워드 검색: project:name, project:site, description, document:title, document:keywords 대상
- 공간 검색: 지도에서 영역 선택 (bbox 교차)
- 시간 검색: datetime 범위 슬라이더
- 유형 필터: data_category 체크박스
- 속성 필터 (고급): proj:epsg, pc:count > N 등 CQL2 기반

**지도 → 결과 목록 연동**: 지도 영역 변경 시 결과 목록 자동 갱신. 결과 목록에서 항목 hover 시 지도에서 해당 위치 강조.

**결과 항목 클릭 → Detail 진입**: 결과 목록에서 Item 클릭 시 오른쪽 슬라이드 패널로 Detail 표시 (페이지 전환 없음). 또는 새 페이지로 이동하는 옵션도 제공.


### 페이지 2: Detail (상세 조회)

**목적**: 특정 Item의 모든 정보를 확인한다.

**주 사용자**: Searcher (1순위), Processor (2순위)

**진입 경로**: Explorer 결과 클릭, Project 대시보드에서 Item 클릭, URL 직접 접근

**연관관계 그래프**: 현재 Item을 중심으로 연결된 모든 Item을 노드-엣지 그래프로 시각화. 각 노드 클릭 시 해당 Item으로 이동.

**시계열 네비게이션**: links에 prev/next가 있으면 타임라인 바 표시. 이전/다음 시점으로 바로 이동 가능.

**편집 모드**: "편집" 버튼 클릭 시 메타데이터 수정 가능 (Draft Item의 경우 Published로 전환도 가능).

### 페이지 4: Upload (데이터 등록)

**목적**: 새 데이터를 시스템에 등록한다.

**주 사용자**: Acquirer (1순위), Processor (2순위)

**구성**: 기존 와이어프레임 활용 — 단, 다른 페이지 설계에 따라 지속 업데이트 예정
- 탭 1: 단건 업로드 (4-step: 파일업로드 → 메타데이터 → 관계설정 → 제출)
- 탭 2: 벌크 업로드 (3-step: 폴더업로드+분석 → 매니페스트편집 → 제출)

**Collection 연동**: Upload 시 Collection 선택이 필수. Collection의 default_epsg가 좌표계 초기값으로 자동 완성. Collection의 project:name, project:site가 Item의 동명 필드로 자동 완성.

**업데이트 예정 사항** (다른 페이지 설계 완료 후):
- 단건 와이어프레임: `pc:coordinate_system` → `proj:epsg` 통일 반영, v4.0 필드 동기화
- Collection 생성 폼과의 연동: Upload 진입 시 Collection이 없으면 "먼저 프로젝트를 생성하세요" 안내 또는 인라인 생성
- 등록 완료 후 이동 경로: "Detail에서 보기" + "Project 대시보드로 이동" 선택지 제공
- Draft 전환: "임시 저장" 선택 시 Project 페이지 Draft 탭에서 이어서 편집 가능하다는 안내 추가

## 5. 역할별 사용 동선

### 동선 A: 현장 담당자 (Acquirer)
```
Upload(벌크) → 폴더 업로드 → 매니페스트 편집 → 등록 → 완료
```
가장 짧은 동선. Upload 페이지만 주로 사용. Explorer는 가끔.

### 동선 B: 후처리 담당자 (Processor)
```
Explorer → 원본 데이터 검색 → Detail에서 확인/다운로드
→ (오프라인 후처리)
→ Upload → 가공 결과 등록 (derived_from으로 원본 연결)
```
Explorer와 Upload를 번갈아 사용. Detail에서 원본 데이터의 메타데이터를 확인하고 다운로드.

### 동선 C: PM (Manager)
```
Project → Collection 생성 (예상 산출물 입력) → (팀원이 데이터 등록)
→ Project 대시보드 → 등록 현황 표로 수량 확인
→ Project 공간 현황 지도 → 어떤 영역에 어떤 유형이 있는지 공간적 확인
→ Explorer → 과거 유사 프로젝트 검색 → 제안서 참고
```
Project 페이지가 주 무대. 등록 현황은 표(수량 기반)와 지도(공간 기반) 두 가지 뷰로 확인. Explorer도 빈번하게 사용.

### 동선 D: 미래의 검색자 (Searcher)
```
Explorer → 키워드/지도/시간으로 검색 → 결과 탐색
→ Detail → 메타데이터 확인 → 관계 그래프로 관련 데이터 발견
→ 파일 다운로드 또는 정보 확인
```
Explorer가 진입점. Detail에서 시간을 많이 보냄. 관계 그래프가 특히 중요 — 원래 찾던 것 외에 관련 데이터를 발견하는 경로.

## 6. 단건 업로드 vs 벌크 업로드 — 존재 이유 정리

| 기준 | 단건 업로드 | 벌크 업로드 |
|------|-----------|-----------|
| 사용 상황 | 특정 파일 1~2개를 정밀하게 등록 | 프로젝트 산출물 다수를 한꺼번에 등록 |
| 핵심 가치 | 정밀도 — 모든 메타데이터 필드를 화면에서 직접 확인·편집 | 효율성 — 여러 파일의 공통 값 일괄 입력, Excel 편집 |
| 메타데이터 편집 | 구역 A/B/C가 펼쳐진 상태로 모든 필드 노출 | 테이블의 공통 컬럼 + ▶ 펼침으로 상세 편집 |
| 관계 설정 | 전용 Step에서 시각적 그래프로 설정 | 매니페스트 컬럼 또는 Excel에서 텍스트로 설정 |
| 전형적 사용자 | 후처리 담당자 (가공 결과 1건을 원본과 연결하여 등록) | 현장 담당자/PM (프로젝트 완료 후 전체 산출물 일괄 등록) |

## 7. 와이어프레임 제작 계획

### 완료된 것 (다른 페이지에 따라 업데이트 예정)
- Upload 페이지: 단건 (v1.0), 벌크 (v2.0)
- → Explorer, Detail, Project 와이어프레임 완료 후 Collection 연동, 필드명 동기화, 완료 후 이동 경로 등을 반영하여 업데이트

### 다음으로 제작할 것 (권장 순서)
1. **Explorer** — 시스템의 핵심 가치(검색)를 직접 보여주는 화면
2. **Detail** — Explorer에서 클릭하면 도달하는 화면
3. **Project** — Collection 생성 폼 + 대시보드 + 공간 현황 지도(F-9) + Draft 관리

### 단건/벌크 업로드 업데이트 예정 사항
Upload 페이지(4페이지 4) 섹션에 상세 기재. Explorer, Detail, Project 완료 후 일괄 반영.
