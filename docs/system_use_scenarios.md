# Spatial Asset Management System — 사용 시나리오

## 1. 시스템의 존재 이유

### 현재 상황 (AS-IS)

우리 회사는 문화재, 건축물, 인프라 등을 대상으로 조사·기록 사업을 수행한다. 한 프로젝트에서 나오는 산출물은 다양하다. LiDAR 포인트 클라우드, 포토그래메트리 3D 모델, 드론 정사영상, 현장 촬영 사진 수백 장, 360° 파노라마, 드론 영상, 그리고 조사 보고서, 실측 도면, 회의록, 허가서 같은 문서류까지. 공간 데이터와 비공간 데이터가 하나의 프로젝트 안에 뒤섞여 있다.

문제는 이 데이터를 관리하는 방식이 10년 전과 다르지 않다는 것이다.

**저장**: 프로젝트별 폴더 → NAS 또는 외장 하드. 폴더 구조는 사람마다 다르다. `2024_불국사/최종/최종_수정/최종_진짜최종/` 같은 상황이 실제로 벌어진다.

**검색**: "3년 전에 불국사 다보탑 스캔한 데이터 어디 있지?" → 담당자에게 물어보거나, 폴더를 뒤지거나, 엑셀 관리대장을 찾는다. 담당자가 퇴사했으면 사실상 찾기 어렵다.

**맥락 유실**: 데이터는 찾았는데, 좌표계가 뭐였는지, 정합 오차가 얼마였는지, 어떤 장비로 찍었는지, 이 보고서가 어떤 스캔 데이터를 기반으로 작성된 것인지 — 이런 맥락 정보가 파일명이나 폴더 구조에 암묵적으로 묻혀 있거나, 아예 유실되어 있다.

**연결 부재**: 다보탑 스캔 데이터와 다보탑 보고서와 다보탑 드론 영상이 같은 대상에 대한 것이라는 관계가 시스템 어디에도 기록되지 않는다. 이것은 사람 머릿속에만 존재한다.

**재활용 실패**: 과거 데이터를 새 프로젝트에서 참고하거나 비교하려 해도, 찾는 데 시간이 너무 오래 걸리거나, 찾더라도 품질·좌표계·범위 등을 확인하는 데 또 시간이 걸린다. 결국 새로 취득하는 것이 더 빠르다는 판단이 반복된다.

**기존 솔루션의 한계**: GIS 솔루션(ArcGIS, QGIS)은 래스터/벡터에 특화되어 있고, 3D 모델·포인트 클라우드·파노라마·동영상·문서를 통합 관리하는 개념이 없다. DAM(Digital Asset Management) 도구는 공간 인덱싱과 좌표계 개념이 없다. 어느 쪽도 "이 보고서와 이 스캔 데이터는 같은 건물에 대한 것"이라는 관계를 표현하지 못한다.

### 이 시스템이 해결하는 것 (TO-BE)

모든 프로젝트 산출물 — 공간이든 비공간이든 — 이 **하나의 시스템에 들어가고, 공간·시간·관계로 연결되며, 누구나 검색으로 찾을 수 있다**.

이것이 되면, 그 위에 "2020년 스캔과 2024년 스캔을 비교해서 변위를 확인한다"거나 "특정 건물에 관련된 모든 데이터를 한 화면에서 본다"같은 고급 활용은 자연스럽게 가능해진다. 기반 인프라가 먼저다.

## 2. 사용자 정의

사내 시스템이므로, 사용자는 모두 같은 회사 소속이다. 역할에 따라 시스템과 만나는 방식이 다르다.

### 역할 A: 현장 담당자 (Data Acquirer)

현장에서 직접 데이터를 취득하는 사람이다. LiDAR 스캐너를 운용하거나, 드론을 날리거나, 카메라로 사진을 찍는다. 현장에서 돌아오면 취득한 데이터를 회사 시스템에 넣어야 한다. 이 사람에게 중요한 것은 **데이터를 빠르고 정확하게 시스템에 올리는 것**이다. 메타데이터를 세세하게 입력하는 것보다 현장에서 다음 일정으로 넘어가는 것이 급하다. 시스템이 자동으로 채워줄 수 있는 것은 최대한 자동으로 채워줘야 한다.

### 역할 B: 후처리 담당자 (Data Processor)

현장 데이터를 받아서 정합, 3D 모델링, 정사영상 생성 등 후처리를 수행하는 사람이다. 원본(raw) 데이터를 입력으로 받아 가공된(processed) 데이터를 산출한다. 이 사람에게 중요한 것은 **원본 데이터에 빠르게 접근하는 것, 그리고 가공 결과를 원본과 연결해서 등록하는 것**이다. "다보탑 스캔 원본 3개를 정합해서 하나의 통합 모델을 만들었다"는 관계가 기록되어야 한다.

### 역할 C: PM / 프로젝트 관리자 (Project Manager)

프로젝트 전체를 관리하는 사람이다. 이 사람에게 중요한 것은 **프로젝트 산출물의 현황 파악**이다. 어떤 데이터가 등록되었고, 무엇이 아직 빠져 있는지, 보고서 납품에 필요한 데이터가 모두 갖춰졌는지를 한눈에 보고 싶다. 또한 과거 유사 프로젝트의 데이터를 참고하기 위해 검색을 자주 사용한다.

### 역할 D: 미래의 검색자 (Future Searcher)

지금 당장은 특정되지 않지만, **6개월 후, 1년 후, 3년 후에 과거 데이터를 찾아야 하는 사람**이다. 본인이 직접 취득한 데이터가 아닐 수도 있다. 당시 담당자가 퇴사했을 수도 있다. 이 사람이 의존할 수 있는 것은 오직 시스템에 기록된 메타데이터와 관계 정보뿐이다. 이 역할이 시스템의 존재 이유를 가장 직접적으로 증명한다.

## 3. 핵심 시나리오

### 시나리오 1: 프로젝트 데이터 일괄 등록

**상황**: 2024년 봄 불국사 정밀실측 프로젝트가 완료되었다. 현장 취득 + 후처리 결과물이 모두 나왔다. 산출물 목록은 다음과 같다.

| # | 데이터 | 유형 | 크기 |
|---|--------|------|------|
| 1 | 다보탑 LiDAR 스캔 (3 스테이션) | 포인트 클라우드 | 2.1 GB |
| 2 | 석가탑 LiDAR 스캔 (4 스테이션) | 포인트 클라우드 | 1.9 GB |
| 3 | 대웅전 LiDAR 스캔 (8 스테이션) | 포인트 클라우드 | 4.3 GB |
| 4 | 다보탑 포토그래메트리 모델 | 3D 모델 | 856 MB |
| 5 | 불국사 전체 드론 정사영상 | 정사영상 | 3.2 GB |
| 6 | 다보탑 촬영 원본 (450장) | 원본 이미지 | 18.7 GB |
| 7 | 석가탑 촬영 원본 (380장) | 원본 이미지 | 15.2 GB |
| 8 | 대웅전 내부 360° 파노라마 | 파노라마 | 45 MB |
| 9 | 불국사 드론 촬영 영상 | 동영상 | 1.82 GB |
| 10 | 정밀실측 보고서 | 문서 (PDF) | 24.5 MB |
| 11 | 현장 조사 일지 | 문서 (XLSX) | 2.1 MB |
| 12 | 문화재청 허가서 | 문서 (PDF) | 1.3 MB |

**AS-IS**: 프로젝트 완료 후 담당자가 NAS의 `2024_불국사_정밀실측` 폴더에 파일을 정리해서 넣는다. 폴더 구조는 담당자 재량이다. 별도 엑셀 대장에 "2024-05-30 / 불국사 / 정밀실측 / 홍길동" 정도를 적는다. 파일별 좌표계, 장비, 정합 오차 같은 정보는 기록되지 않는다.

**TO-BE — 시스템에서의 흐름**:

**① 프로젝트(Collection) 생성**
PM이 시스템에서 "2024 경주 불국사 정밀실측"이라는 Collection을 생성한다. 여기에 프로젝트 메타데이터(발주처, 기간, 대상 사이트, 좌표계 기준)를 입력한다. 이 Collection은 앞으로 등록되는 모든 데이터의 소속이 된다.

**② 벌크 업로드 — 폴더 통째로**
후처리 담당자(또는 현장 담당자)가 프로젝트 폴더를 시스템에 업로드한다. 시스템이 폴더를 스캔하고 12개 파일/파일셋을 자동 인식한다. 각 파일에서 추출 가능한 메타데이터(포인트 수, 좌표계, 해상도, 코덱, 촬영일 등)를 자동으로 읽어낸다. 사용자 화면에 자동 추출값이 미리 채워진 매니페스트 테이블이 나타난다.

**③ 매니페스트 편집 — 빈 칸 채우기**
일괄 입력 바에서 "사이트: 경주 불국사", "좌표계: EPSG:5186"을 입력하고 "전체 적용"을 누른다. 12개 행에 공통값이 한번에 채워진다. 그 다음, 행별로 다른 값만 개별 수정한다: 대상 세부 위치(다보탑/석가탑/대웅전/전체), 데이터 설명, 문서 제목·저자 등. ▶ 버튼으로 포인트 클라우드 행을 펼쳐서 "스캐너: Leica RTC360", "PC 유형: lidar"를 입력한다.

**④ 관계 설정**
"다보탑 3D 모델"의 관계 설정에서 "원본: 다보탑 촬영 원본 450장"과 "관련: 다보탑 LiDAR 스캔"을 연결한다. "정밀실측 보고서"는 "관련: 모든 스캔/모델 데이터"로 연결한다. 이 관계 정보가 STAC links에 `derived_from`, `related`, `describedby`로 기록된다.

**⑤ 일괄 등록**
검토 화면에서 12개 Item의 메타데이터를 최종 확인하고 "일괄 등록" 버튼을 누른다. 파일이 S3(MinIO)에 업로드되고, STAC Item 12개가 pgSTAC에 생성된다. 이 시점부터 이 데이터는 시스템에서 검색 가능하다.

**소요 시간 비교**:
- AS-IS: 폴더 정리 + NAS 복사 + 엑셀 대장 작성 = 30~60분. 맥락 정보 기록 없음.
- TO-BE: 폴더 업로드 + 매니페스트 편집 = 15~20분. 모든 맥락이 검색 가능한 형태로 기록됨.

### 시나리오 2: 과거 데이터 검색

**상황**: 6개월 후, 다른 담당자(김과장)가 경주 지역 신규 프로젝트를 수주했다. 제안서를 쓰는데, "우리 회사가 불국사 관련 데이터를 이미 갖고 있나?"를 확인하고 싶다. 원래 담당자(홍대리)는 지금 다른 현장에 나가 있어서 바로 물어보기 어렵다.

**AS-IS**: 김과장이 NAS에서 "불국사"를 파일명 검색한다. `2024_불국사_정밀실측` 폴더를 찾는다. 폴더를 열어보면 하위 폴더가 여러 개 있는데, 뭐가 뭔지 한눈에 파악이 안 된다. `pointcloud` 폴더에 .laz 파일이 3개 있는데, 각각 어디를 스캔한 건지 파일명만으로는 모호하다. 좌표계가 뭔지, 품질이 어떤지 알 수 없다. 결국 홍대리에게 메신저로 물어보고 답을 기다린다.

**TO-BE — 시스템에서의 흐름**:

**① 검색**
김과장이 시스템 검색 화면에서 키워드 "불국사"를 입력한다. 또는 지도 뷰에서 경주 불국사 영역을 마우스로 선택한다. 또는 둘 다 조합한다.

**② 검색 결과**
"2024 경주 불국사 정밀실측" Collection이 나타나고, 그 안에 12개 Item이 목록으로 보인다. 각 Item에는 유형 아이콘, 데이터 설명, 취득일, 크기, 썸네일이 표시된다. 지도 위에 각 데이터의 공간 범위가 시각화된다. 문서류(보고서, 일지, 허가서)도 해당 건물 위에 마커로 보인다 — 왜냐하면 등록 시 문서의 geometry를 대상 건물 위치로 설정했기 때문이다.

**③ 데이터 상세 확인**
김과장이 "다보탑 LiDAR 스캔"을 클릭한다. 상세 화면에서 이런 정보를 바로 확인할 수 있다:
- 포인트 수: 15,230,482
- 좌표계: EPSG:5186
- 스캐너: Leica RTC360
- 취득일: 2024-03-12
- 정합 오차: 0.003m RMSE
- 관련 데이터: 다보탑 3D 모델 (이 스캔에서 파생), 정밀실측 보고서 (이 스캔을 참조)

홍대리에게 물어볼 필요가 없다. 모든 맥락이 시스템에 기록되어 있다.

**④ 데이터 재활용 결정**
김과장은 이 정보를 보고 "불국사 일대의 기존 데이터가 있으니, 신규 프로젝트에서 이 영역은 재취득할 필요가 없다"는 판단을 내린다. 제안서에 "당사 보유 기존 데이터 활용 가능"이라고 적고, 시스템에서 썸네일과 메타데이터 요약을 캡처해서 첨부한다.

### 시나리오 3: 반복 조사 — 시계열 연결

**상황**: 2년 후(2026년), 불국사 다보탑에 대한 후속 조사가 발주되었다. 동일 대상에 대한 2차 스캔이다.

**AS-IS**: 담당자가 2024년 스캔 데이터를 NAS에서 찾는다. 찾아도, 2024년 데이터와 2026년 데이터를 "같은 대상의 시점 다른 데이터"로 연결하는 방법이 없다. 두 데이터가 같은 좌표계인지, 비교 가능한 상태인지 일일이 확인해야 한다.

**TO-BE — 시스템에서의 흐름**:

**① 기존 데이터 확인**
2026년 프로젝트 시작 시, 담당자가 시스템에서 "불국사 다보탑"을 검색한다. 2024년 데이터가 즉시 나타난다. 좌표계, 스캐너 모델, 정합 방법 등을 확인하고, 2026년 조사의 사양을 이전과 호환되게 설정한다.

**② 새 Collection + Item 등록**
"2026 경주 불국사 다보탑 변위 조사"라는 새 Collection을 만들고, 새로 취득한 데이터를 등록한다.

**③ 시계열 관계 설정**
"2026 다보탑 스캔"의 관계 설정에서 "이전 시점: 2024 다보탑 스캔 (bulguksa-dabotap-pc-20240312)"을 연결한다. STAC links에 `rel: "previous"` 또는 커스텀 `rel: "same_target_previous"`로 기록된다.

**④ 향후 활용 가능성**
이 시계열 관계가 기록되어 있으면, 나중에 "다보탑의 모든 시점 데이터를 시간순으로 보여줘"라는 쿼리가 가능해진다. 변위 분석 애플리케이션을 개발할 때, 데이터를 찾고 연결하는 작업이 이미 끝나 있는 상태가 된다.

---

### 시나리오 4: 프로젝트 현황 관리

**상황**: PM이 진행 중인 프로젝트의 데이터 등록 현황을 파악하고 싶다. "현장은 끝났는데 아직 시스템에 안 올라온 데이터가 뭐가 있지?"

**AS-IS**: PM이 담당자들에게 일일이 물어본다. "스캔 데이터 정리했어?", "보고서 최종본 나왔어?", "드론 영상은?" 답변을 취합해서 엑셀에 정리한다.

**TO-BE — 시스템에서의 흐름**:

**① Collection 대시보드**
PM이 "2024 경주 불국사 정밀실측" Collection을 연다. 대시보드에 등록된 Item 현황이 보인다:
- 포인트 클라우드: 3/3건 (완료)
- 3D 모델: 1/2건 (석가탑 모델 미등록)
- 정사영상: 1/1건 (완료)
- 원본 이미지: 2/2건 (완료)
- 파노라마: 1/3건 (대웅전만 등록, 다보탑·석가탑 미등록)
- 동영상: 1/1건 (완료)
- 문서: 2/3건 (보고서·일지 등록, 허가서 미등록)

**② 미등록 항목 확인 및 조치**
PM이 미등록 항목을 확인하고, 담당자에게 "석가탑 모델은 언제 올라오나?", "파노라마 2건 빠졌다" 같은 구체적 지시를 할 수 있다.

이 시나리오가 작동하려면 Collection 생성 시 "예상 산출물 목록"을 미리 정의하는 기능이 필요하다. 이것은 현재 메타데이터 설계에 없으므로, **Collection 수준의 메타데이터 확장**이 필요한 지점이다.

### 시나리오 5: 비공간 데이터의 공간적 활용

**상황**: 회사 라이브러리에 수년간 쌓인 보고서, 도면, 허가서 같은 문서가 수백 건 있다. 이것들은 현재 파일 서버에 프로젝트별 폴더로만 정리되어 있다. 어떤 지역에 대한 문서가 있는지 알려면 폴더를 하나하나 뒤져야 한다.

**AS-IS**: "경주 지역에 우리가 작업한 프로젝트가 뭐가 있지?" → 프로젝트 목록 엑셀을 검색하거나, 기억에 의존한다.

**TO-BE — 시스템에서의 흐름**:

**① 기존 문서 일괄 등록**
기존 문서들을 시스템에 등록할 때, 각 문서의 geometry를 해당 사이트 위치로 설정한다. "불국사 보고서"면 불국사 위치에, "해인사 도면"이면 해인사 위치에. 이 작업은 한 번만 하면 된다.

**② 지도 기반 검색**
이제 시스템의 지도 뷰에서 한국 전체 지도를 보면, 회사가 보유한 모든 데이터(스캔, 모델, 문서 등)가 위치별로 점으로 표시된다. 특정 지역을 확대하면 해당 지역의 모든 데이터 — 공간 데이터와 비공간 데이터 모두 — 가 나타난다.

**③ 지역 기반 포트폴리오**
신규 프로젝트 제안 시, "이 지역에서 우리가 이전에 수행한 프로젝트와 보유 데이터"를 지도 위에서 한눈에 보여줄 수 있다. 이것은 영업 도구로도 활용 가능하다.

## 시나리오 6: 발주처 프레젠테이션 (Phase 2)

### 상황
PM(역할 C)이 문화재청에 중간 보고를 한다. "지금까지 이만큼 데이터를 모았고, 이렇게 보입니다"를 시각적으로 보여주고 싶다.

### AS-IS
PM이 NAS에서 대표 파일 몇 개를 골라 CloudCompare에서 열어 스크린샷을 찍고, 파워포인트에 붙이고, 산출물 목록을 수동으로 표에 정리한다. 준비에 반나절이 걸린다.

### TO-BE (Phase 2)
PM이 SAMS의 Project 페이지를 연다. 등록 현황 대시보드가 "15건 중 12건 등록, 80% 완료"를 보여준다. 공간 현황 지도에서 어떤 영역에 어떤 유형이 있는지 확인한다. 타임라인 플레이를 실행하면 3월부터 4월까지 데이터가 하나씩 지도에 나타나면서 축적 과정을 보여준다. 대표 Item을 클릭하면 3D 미리보기로 포인트 클라우드가 브라우저에서 바로 돌아간다. 이 화면 자체가 프레젠테이션이다.

### Phase 1에서의 대안
Phase 1에서도 발주처 보고는 가능하다. Project 대시보드의 등록 현황 표, 공간 현황 2D 지도, 썸네일이 화면 공유만으로도 "파워포인트 수동 정리"보다 낫다.
