# SAMS 시스템 구조 설계서

## 1. 시스템 개요

### 시스템명
Spatial Asset Management System (SAMS)

### 핵심 가치
모든 프로젝트 산출물(공간+비공간)을 하나의 시스템에서 안전하게 보관하고, 누구나 검색으로 찾을 수 있게 한다. 또한 산출물의 위치·유형·상태·관계를 3D 공간에서 이해할 수 있게 한다.

### 차별성 — 다른 뷰어·관리도구와 무엇이 다른가
SAMS의 차별성은 **메타데이터 자동 채움**이다. 기존 3D 뷰어(Potree, Cesium ion)나 GIS 관리도구(GeoServer, GeoNode)는 데이터를 "보는 것"이나 "서빙하는 것"에 집중하지만, **데이터를 시스템에 넣는 과정 자체를 최소화하는 것**에는 관심이 적다. SAMS는 파일을 올리면 시스템이 메타데이터를 최대한 자동으로 채우고, 사용자는 기계가 알 수 없는 맥락 정보만 입력한다. 이것이 NAS 폴더 + 스프레드시트 대비 SAMS를 채택해야 하는 이유이며, 다른 도구와의 핵심 차별점이다.

### 시스템 채택의 전제 조건
메타데이터 자동 채움은 "있으면 좋은 기능"이 아니라 **"없으면 시스템이 실패하는 조건"**이다. 현재의 AS-IS(NAS 폴더 복사)보다 이 시스템에 올리는 것이 **체감적으로 더 쉽지 않으면** 아무도 쓰지 않는다. 따라서 자동 채움 파이프라인은 Phase 1의 최우선 구현 대상이며, 다른 모든 기능보다 앞선다.

### 3D의 역할 — 핵심 기능과 헤비 뷰어의 구분
SAMS에서 3D는 핵심 기능이다. 다만 v1에서 말하는 핵심 3D는 Potree/Cesium 같은 production heavy asset viewer가 아니라, 등록된 산출물들이 어디에 있고 서로 어떤 관계인지 공간적으로 이해하게 하는 **3D Spatial Relationship View**다.

v1의 3D는 map-grounded 3D 화면에서 현재 검색 결과, 선택 Item, 1-depth 관계선, 관계 유형, 상태, 유형, 프로젝트 맥락을 함께 보여주는 것을 목표로 한다. 개별 포인트클라우드·3D Tiles·모델 파일을 브라우저에서 고품질로 직접 렌더링하는 viewer, COPC/GLB/COG 변환 파이프라인, 외부 공유형 쇼케이스는 Phase 2 범위로 둔다.

### 사용자
사내 전용. 같은 회사 소속 4가지 역할.

### 접근 정책
현 단계(사내 전용)에서는 **모든 사용자가 모든 기능에 접근 가능**하다. 역할 구분은 권한 제어가 아니라, 화면 설계의 우선순위를 정하기 위한 것이다. "주 사용자"는 "이 화면을 설계할 때 가장 먼저 고려하는 역할"을 의미한다. 향후 클라이언트에게 시스템을 열 때 역할 기반 권한 분리를 도입할 수 있으며, 현재의 역할 정의가 그 기반이 된다.

## 2. 사용자 역할 정의

| 역할 | 약칭 | 핵심 동기 | 시스템 사용 빈도 |
|------|------|----------|----------------|
| 현장 담당자 | Acquirer | 취득 데이터를 빠르게 시스템에 넣고 싶다 | 프로젝트 완료 시 집중 사용 |
| 후처리 담당자 | Processor | 원본을 찾아 가공하고, 결과를 원본과 연결해 등록하고 싶다 | 프로젝트 진행 중 지속 사용 |
| PM | Manager | 산출물 현황을 파악하고, 과거 데이터를 참고하고 싶다 | 상시 사용 |
| 미래의 검색자 | Searcher | 과거 데이터를 맥락 정보 없이 찾아야 한다 | 불시 사용 (가장 중요한 역할) |

## 3. 화면 구조 (4페이지)

### 전체 레이아웃

```
┌─────────────────────────────────────────────────┐
│  상단 네비게이션 바                                │
│  [Explorer]  [Project]  [Upload]  [사용자메뉴]      │
├─────────────────────────────────────────────────┤
│                                                 │
│              각 페이지 콘텐츠 영역                  │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 페이지 1: Explorer (탐색/검색)

**목적**: 데이터를 찾는다. 시스템의 홈이자 가장 많이 쓰는 화면.

**주 사용자**: Searcher (1순위), Manager (2순위), Processor (3순위)

**구성**:
```
┌──────────────────────────────────────────────────────┐
│ Explorer                                              │
├────────────┬─────────────────────────────────────────┤
│            │                                         │
│  검색 필터  │              2D 지도                     │
│  패널      │         (데이터 위치 시각화)               │
│            │                                         │
│ ┌────────┐ │                                         │
│ │키워드   │ │    [●] 포인트클라우드                     │
│ │검색     │ │    [△] 3D모델                           │
│ └────────┘ │    [▤] 문서    ← 문서도 지도에 마커       │
│            │                                         │
│ ┌────────┐ ├─────────────────────────────────────────┤
│ │유형 필터│ │                                         │
│ │시간 범위│ │         검색 결과 목록                    │
│ │좌표계   │ │  ┌─────────────────────────────────┐    │
│ │사이트   │ │  │ ⦿ 다보탑 LiDAR 스캔              │    │
│ │프로젝트 │ │  │   2024-03-12 · 15M pts · 2.1GB  │    │
│ └────────┘ │  ├─────────────────────────────────┤    │
│            │  │ △ 다보탑 포토그래메트리 모델        │    │
│ ┌────────┐ │  │   2024-03-15 · 1.2M vertex       │    │
│ │속성 필터│ │  ├─────────────────────────────────┤    │
│ │(고급)  │ │  │ ▤ 정밀실측 보고서                 │    │
│ └────────┘ │  │   2024-04-15 · PDF · 156쪽       │    │
│            │  └─────────────────────────────────┘    │
└────────────┴─────────────────────────────────────────┘
```

**검색 방식**:
- 키워드 검색: project:name, project:site, description, document:title, document:keywords 대상
- 공간 검색: 지도에서 영역 선택 (bbox 교차)
- 시간 검색: datetime 범위 슬라이더
- 유형 필터: data_category 체크박스
- 속성 필터 (고급): proj:epsg, pc:count > N 등 CQL2 기반

**지도 → 결과 목록 연동**: 지도 영역 변경 시 결과 목록 자동 갱신. 결과 목록에서 항목 hover 시 지도에서 해당 위치 강조.

**결과 항목 클릭 → 미리보기 패널**: 결과 목록에서 Item 클릭 시 오른쪽 슬라이드 패널로 미리보기 표시 (페이지 전환 없음). 패널에서 "상세 보기" 클릭 시 전체 페이지로 이동.


### 페이지 2: Detail (상세 조회) — 이중 구조

**목적**: 특정 Item의 정보를 확인한다.

**주 사용자**: Searcher (1순위), Processor (2순위)

**이중 구조 설계 근거**:
- "훑어보기" vs "깊이 파기"라는 두 가지 사용 맥락이 존재
- 훑어보기: 검색 결과를 빠르게 넘기며 "이것이 내가 찾는 데이터인가?" 판단 → Explorer를 떠나지 않아야 함
- 깊이 파기: 특정 Item의 관계를 따라가고, 시계열을 비교하고, 메타데이터를 편집 → 전체 화면 필요

#### 2-A. 미리보기 패널 (Explorer 내 슬라이드)

**진입 경로**: Explorer 결과 클릭, Explorer 지도 마커 클릭
**표시 방식**: Explorer 오른쪽에서 슬라이드 (폭 ~380px), Explorer 지도/결과 목록 유지
**용도**: 빠른 판단 — "이 데이터가 맞나?" → 맞으면 상세 보기 또는 다운로드, 아니면 닫고 다음 Item

```
┌───────── Explorer (좁아짐) ──────┬──── 미리보기 패널 ────┐
│ 지도 + 결과 목록 유지             │                      │
│                                 │ ⦿ 포인트 클라우드       │
│ (다른 Item을 바로 클릭하여        │ 다보탑 LiDAR 스캔      │
│  패널 내용을 전환할 수 있음)       │ 경주 불국사 · 다보탑    │
│                                 │ 2024-03-12 · 2.1GB    │
│                                 │                      │
│                                 │ 핵심 메타데이터         │
│                                 │ ├ 포인트: 15.2M       │
│                                 │ ├ 밀도: 248 pts/m²    │
│                                 │ ├ 좌표계: EPSG:5186   │
│                                 │ └ 스캐너: Leica RTC360│
│                                 │                      │
│                                 │ 관련 데이터 (4건)      │
│                                 │ ├ △ 다보탑 3D 모델    │
│                                 │ ├ ▣ 다보탑 이미지     │
│                                 │ ├ ▤ 보고서           │
│                                 │ └ ⦿ 2023년 스캔      │
│                                 │                      │
│                                 │ [다운로드] [상세 보기→] │
│                                 │         ↑             │
│                                 │    전체 페이지로 이동   │
└─────────────────────────────────┴──────────────────────┘
```

**패널에 포함되는 것**:
- 유형 뱃지 + 제목 + 핵심 태그 (사이트, 날짜, 크기)
- 핵심 메타데이터 요약 (자동추출 상위 4~5개 + 수동입력 상위 2~3개)
- 관련 데이터 목록 (클릭 시 패널 내에서 전환)
- 시계열 간이 표시 (prev/next 있을 때 "← 2023 | **현재** | →" 수준)
- [다운로드] [상세 보기 →] 버튼

**패널에 포함되지 않는 것** (전체 페이지에서만):
- 관계 그래프 시각화 (공간이 부족)
- 시계열 비교 카드 (공간이 부족)
- 메타데이터 편집 모드
- 전체 메타데이터 (자동추출 전부 + 수동입력 전부)
- 공간 정보 미니맵

#### 2-B. 전체 페이지 (상세 보기)

**진입 경로**: 미리보기 패널의 "상세 보기" 버튼, Project Item 목록 클릭, URL 직접 접근
**표시 방식**: 전체 페이지 전환 (Explorer를 떠남)
**용도**: 깊이 파기 — 모든 메타데이터 확인, 관계 그래프 탐색, 시계열 비교, 편집

```
┌──────────────────────────────────────────────────────┐
│ ← Explorer로 돌아가기   [Explorer] [Project] [Upload] │
├──────────────────────────────────────────────────────┤
│ Explorer > 2024 불국사 정밀실측 > 다보탑 LiDAR 스캔     │
├──────────────────────────────────────────────────────┤
│                                                      │
│ [썸네일]  ⦿ 포인트 클라우드                            │
│           다보탑 LiDAR 스캔                           │
│           설명 텍스트...                               │
│           📍 경주 불국사 · 다보탑  📅 2024-03-12       │
│           📐 EPSG:5186  🏢 (주)공간정보기술  ✅ Published│
│                                                      │
├──────────────────────────────────────────────────────┤
│ [📋 메타데이터] [📁 파일(4)] [🔗 연관관계(4)] [⏱ 시계열] [✏️ 편집] │
├──────────────────────────────────────────────────────┤
│                                                      │
│  선택된 탭 콘텐츠 (전체 화면 폭 활용)                    │
│                                                      │
│  📋 메타데이터: 2×2 그리드 카드                         │
│  📁 파일: Asset 목록 + 다운로드                         │

│                                                      │

```

**전체 페이지에서만 가능한 것**:
- 관계 그래프 시각화 (넓은 공간 활용)
- 시계열 비교 카드 (시점별 메타데이터 나란히 비교)
- 메타데이터 편집 모드 (Draft→Published 전환 포함)
- 전체 메타데이터 열람 (자동추출·수동입력 모두)
- 공간 정보 미니맵 (bbox 시각화)

**"← Explorer로 돌아가기" 동작**: 이전 검색 상태(필터, 스크롤 위치)를 유지한 채 Explorer로 복귀. 검색 결과를 다시 불러올 필요 없음.

### 페이지 4: Upload (데이터 등록)

**목적**: 새 데이터를 시스템에 등록한다.

**주 사용자**: Acquirer (1순위), Processor (2순위)

**구성**: 기존 와이어프레임 활용 — 단, 다른 페이지 설계에 따라 지속 업데이트 예정
- 탭 1: 단건 업로드 (4-step: 파일업로드 → 메타데이터 → 관계설정 → 제출)
- 탭 2: 벌크 업로드 (3-step: 폴더업로드+분석 → 매니페스트편집 → 제출)

**Collection 연동**: Upload 시 Collection 선택이 필수. Collection의 default_epsg가 좌표계 초기값으로 자동 완성. Collection의 project:name, project:site가 Item의 동명 필드로 자동 완성.

**업데이트 예정 사항** (다른 페이지 설계 완료 후):
- 단건 와이어프레임: `pc:coordinate_system` → `proj:epsg` 통일 반영, v4.0 필드 동기화
- Collection 생성 폼과의 연동: Upload 진입 시 Collection이 없으면 "먼저 프로젝트를 생성하세요" 안내 또는 인라인 생성
- 등록 완료 후 이동 경로: "Detail에서 보기" + "Project 대시보드로 이동" 선택지 제공
- Draft 전환: "임시 저장" 선택 시 Project 페이지 Draft 탭에서 이어서 편집 가능하다는 안내 추가

## 5. 역할별 사용 동선

### 동선 A: 현장 담당자 (Acquirer)
```
Upload(벌크) → 폴더 업로드 → 매니페스트 편집 → 등록 → 완료
```
가장 짧은 동선. Upload 페이지만 주로 사용. Explorer는 가끔.

### 동선 B: 후처리 담당자 (Processor)
```
Explorer → 원본 데이터 검색 → Detail에서 확인/다운로드
→ (오프라인 후처리)
→ Upload → 가공 결과 등록 (derived_from으로 원본 연결)
```
Explorer와 Upload를 번갈아 사용. Detail에서 원본 데이터의 메타데이터를 확인하고 다운로드.

### 동선 C: PM (Manager)
```
Project → Collection 생성 (예상 산출물 입력) → (팀원이 데이터 등록)
→ Project 대시보드 → 등록 현황 표로 수량 확인
→ Project 공간 현황 지도 → 어떤 영역에 어떤 유형이 있는지 공간적 확인
→ Explorer → 과거 유사 프로젝트 검색 → 제안서 참고
```
Project 페이지가 주 무대. 등록 현황은 표(수량 기반)와 지도(공간 기반) 두 가지 뷰로 확인. Explorer도 빈번하게 사용.

### 동선 D: 미래의 검색자 (Searcher)
```
Explorer → 키워드/지도/시간으로 검색 → 결과 탐색
→ Detail → 메타데이터 확인 → 관계 그래프로 관련 데이터 발견
→ 파일 다운로드 또는 정보 확인
```
Explorer가 진입점. Detail에서 시간을 많이 보냄. 관계 그래프가 특히 중요 — 원래 찾던 것 외에 관련 데이터를 발견하는 경로.

## 6. 단건 업로드 vs 벌크 업로드 — 존재 이유 정리

| 기준 | 단건 업로드 | 벌크 업로드 |
|------|-----------|-----------|
| 사용 상황 | 특정 파일 1~2개를 정밀하게 등록 | 프로젝트 산출물 다수를 한꺼번에 등록 |
| 핵심 가치 | 정밀도 — 모든 메타데이터 필드를 화면에서 직접 확인·편집 | 효율성 — 여러 파일의 공통 값 일괄 입력, Excel 편집 |
| 메타데이터 편집 | 구역 A/B/C가 펼쳐진 상태로 모든 필드 노출 | 테이블의 공통 컬럼 + ▶ 펼침으로 상세 편집 |
| 관계 설정 | 전용 Step에서 시각적 그래프로 설정 | 매니페스트 컬럼 또는 Excel에서 텍스트로 설정 |
| 전형적 사용자 | 후처리 담당자 (가공 결과 1건을 원본과 연결하여 등록) | 현장 담당자/PM (프로젝트 완료 후 전체 산출물 일괄 등록) |

## 7. 와이어프레임 및 설계 현황

### Phase 1 설계 — 완료
- Explorer (2D 지도 + 검색 + 미리보기 패널): 와이어프레임 완료
- Detail (미리보기 패널 + 전체 페이지 4탭 + 편집 모드): 와이어프레임 완료
- Project (Collection 목록 + 4탭 대시보드 + 생성 폼): 와이어프레임 완료
- Upload (벌크 3-step + 단건 4-step): 와이어프레임 완료
- 통합 데모 (4페이지 연결, 페이지 간 이동 작동): 완료
- → 모든 와이어프레임은 구현 단계에서 세부 조정 예정

### Phase 1 설계 — 다음 단계 (구현 준비)
1. **메타데이터 자동 채움 파이프라인 명세** ⭐ — 유형별 추출 필드, 라이브러리, 실패 처리
2. **시스템 아키텍처** — docker-compose, 컴포넌트 연결
3. **API 설계** — stac-fastapi 엔드포인트 + 커스텀 엔드포인트
4. **파일 스토리지 전략** — S3 경로 규칙, 업로드 방식
5. **Upload 와이어프레임 업데이트** — v4.0 필드 동기화, Collection 연동 확정

### Phase 2 설계 — 미착수
- Production 3D Tiles/terrain/globe viewer, 타임라인 자동 플레이, 경량 변환 파이프라인, 브라우저 내 3D/PC 미리보기, 외부 공유
- v1의 map-grounded 3D Spatial Relationship View와 구분한다. Phase 2는 개별 대용량 자산을 실제 viewer로 여는 쇼케이스/고급 활용 범위다.

| 5 | 메타데이터 자동 채움 극대화 | 타이핑을 줄여달라 | 데이터 넣는 과정이 번거로우면 안 쓴다 |

### 핵심 시사점

**고객은 3D 공간 이해와 "쇼케이스" 용도를 함께 상상하고 있다.** 피드백 1은 단순 장식이 아니라 산출물이 공간적으로 어디에 있고 서로 어떤 관계인지 알고 싶다는 요구다. 따라서 v1에는 map-grounded 3D Spatial Relationship View를 포함한다. 피드백 2, 3처럼 타임라인 자동재생이나 브라우저 내 포인트클라우드·모델 viewer까지 필요한 프레젠테이션형 쇼케이스는 Phase 2로 둔다.

**그러나 쇼케이스가 작동하려면 보여줄 데이터가 먼저 있어야 한다.** 데이터가 5건인 시스템에서 3D 지구본을 돌려봐야 의미가 없다. 기반(입고+검색)이 먼저이고, 쇼케이스는 기반 위의 레이어라는 원칙은 유효하다.

**피드백 5는 다른 4개와 차원이 다르다.** 1~4는 "있으면 좋겠다"이지만, 5는 "없으면 안 쓴다"이다. 이것이 SAMS의 차별성(시스템 개요 참조)이며, 시스템 채택의 전제 조건이다.

## 9. Phase 계획

### 원칙
"데이터가 쉽게 들어오고(입고), 들어온 데이터를 빠르게 찾고(검색+확인), 산출물 간 공간 관계를 3D로 이해할 수 있는 것(3D 관계 뷰)이 Phase 1. 개별 대용량 자산을 브라우저에서 고품질로 렌더링하고 외부 프레젠테이션에 쓰는 것(헤비 뷰어/쇼케이스)은 Phase 2."

### Phase 1 — 기반 인프라 (입고 + 검색 + 확인)

목표: NAS 폴더 + 스프레드시트를 대체한다. 모든 프로젝트 산출물이 이 시스템에 들어오고, 6개월 후 아무나 검색으로 찾을 수 있다.

| 영역 | 구현 내용 | 근거 |
|------|----------|------|
| **메타데이터 자동 채움** ⭐ | 파일 파싱 파이프라인 (laspy, rasterio, ffprobe, EXIF, trimesh, PyPDF). Collection 기본값 상속 (default_epsg, project:name, project:site). 이전 입력값 자동완성. | 시스템 채택 전제 조건. 가장 먼저 구현. |
| 벌크/단건 업로드 | 폴더 업로드 → 자동 분석 → 매니페스트 편집 → 일괄 등록. 단건 4-step 업로드. | 입고 프로세스의 본체. |
| Collection 관리 | 생성 폼, 기본값 설정, 예상 산출물 정의. | 입고의 전제 (데이터가 속할 곳). |
| STAC API 검색 | stac-fastapi /search 엔드포인트. 키워드, bbox, datetime, data_category, 속성 필터. | 핵심 가치(검색). |
| Explorer (2D) | 검색 필터 사이드바 + 2D 지도 (MapLibre) + 결과 목록 + 미리보기 패널. 시간 범위 슬라이더 (필터링 용도). | 검색의 UI. |
| 3D Spatial Relationship View | Map-grounded 3D 화면에서 현재 검색 결과, 선택 Item, 1-depth 관계선, 관계 유형, 상태, 유형, 프로젝트 맥락을 함께 표시. | 산출물 간 관계를 공간적으로 이해하는 v1 핵심 기능. Heavy asset viewer와는 구분. |
| Detail | 미리보기 패널 (핵심 정보 요약) + 전체 페이지 (메타데이터·파일·연관관계·시계열·편집). | 검색 결과 확인. |
| Project 대시보드 | 등록 현황 표 + 2D 공간 현황 지도 + Draft 관리 + Item 목록. | 프로젝트 관리. |
| 데이터 미리보기 (썸네일) | 업로드 시 썸네일 자동 생성. Detail에서 썸네일 표시. | 검색 판단을 위한 최소한의 시각 정보. |
| Draft→Published | Project Draft 탭 → Detail 편집 모드 → Published 전환. | 입고 완결. |

**Phase 1에서 하지 않는 것**: 타임라인 자동 플레이, 브라우저 내 production 3D/포인트클라우드/3D Tiles 뷰어, COPC/GLB/COG 변환 파이프라인, 외부 공유. 즉, 3D 관계 뷰는 Phase 1 핵심이지만 헤비 자산 뷰어는 Phase 2다.

**Phase 1의 미리보기 전략**: 3D 뷰어 대신 **썸네일**로 시작한다. 업로드 시 파이프라인이 포인트 클라우드/3D 모델/정사영상의 스크린샷을 자동 생성하여 thumbnail Asset으로 등록한다. 검색 결과에서 "이 데이터가 어떻게 생겼는지"를 판단하는 데 썸네일만으로도 상당 부분 가능하다. 이것은 변환 파이프라인 없이 간단한 렌더링 스크립트(open3d, matplotlib)로 구현 가능하다.

### Phase 2 — 쇼케이스 + 고급 활용

목표: Phase 1 기반 위에 시각적 경험을 올린다. 사내 활용뿐 아니라 발주처 프레젠테이션에도 사용 가능.

| 영역 | 구현 내용 | 근거 |
|------|----------|------|
| 경량 변환 파이프라인 | LAS→COPC, OBJ→GLB(decimation+Draco), GeoTIFF→COG. 비동기 worker. 변환 완료 시 Asset 자동 등록. | 3D 미리보기와 경량 다운로드의 전제. |
| 브라우저 내 3D 미리보기 | Potree(COPC 스트리밍), model-viewer(GLB), Pannellum(파노라마). Detail 미리보기 영역에 유형별 뷰어 로드. | 검색 판단 가속. 파일 다운로드 없이 확인. |
| 경량 데이터 다운로드 | 경량 변환 파이프라인의 부산물. Detail 파일 탭에서 원본과 경량본 구분 표시. | 위 파이프라인이 되면 자동으로 가능. |
| Production 3D Tiles/terrain/globe viewer | CesiumJS 등으로 특정 사이트의 3D Tiles, terrain, globe를 실제 렌더링. | v1의 map-grounded 3D 관계 뷰 이후의 고급 viewer. |
| 타임라인 플레이 | 시간 슬라이더 자동 재생. 3D 뷰와 결합하여 시점별 데이터 전환. | 외부 프레젠테이션 시나리오(시나리오 6). |
| 외부 공유 | 읽기 전용 공유 링크. Collection 또는 개별 Item 단위. 권한 제어. | 발주처 보고, 클라이언트 대면. |

## 10. 시나리오 6: 발주처 프레젠테이션 (Phase 2 대상)

### 맥락
PM이 문화재청에 중간 보고를 한다. "지금까지 이만큼의 데이터를 모았고, 이렇게 보입니다"를 시각적으로 보여주고 싶다.

### AS-IS
PM이 NAS에서 대표 파일 몇 개를 골라 CloudCompare에서 열어 스크린샷을 찍고, 파워포인트에 붙이고, 산출물 목록을 수동으로 표에 정리한다. 준비에 반나절.

### TO-BE (Phase 2)
PM이 SAMS의 Project 페이지를 연다. 등록 현황 대시보드가 "15건 중 12건 등록, 80% 완료"를 바로 보여준다. 공간 현황 지도에서 어떤 영역에 어떤 데이터가 있는지 확인한다. 타임라인 플레이를 실행하면 3월 12일부터 4월 15일까지 데이터가 하나씩 지도에 나타나면서 축적 과정을 시각적으로 보여준다. 대표 데이터를 클릭하면 3D 미리보기로 포인트 클라우드나 모델이 브라우저에서 바로 돌아간다. 이 화면 자체가 프레젠테이션이다.

### 왜 Phase 2인가
이 시나리오는 production 3D/포인트클라우드 뷰어, 타임라인 자동재생, 경량 변환 파이프라인이 모두 필요하다. Phase 1에는 산출물 간 관계를 이해하기 위한 3D Spatial Relationship View를 포함하지만, 개별 대용량 자산을 고품질로 렌더링하는 viewer와 외부 발표용 쇼케이스는 **데이터가 시스템에 쉽게 들어오고 관계가 안정적으로 연결된 뒤** 착수한다.

### Phase 1에서의 대안
Phase 1에서도 발주처 보고는 가능하다. Project 대시보드의 등록 현황 표, 공간 현황 2D 지도, 3D Spatial Relationship View, 썸네일 이미지가 화면 공유만으로도 "파워포인트 수동 정리"보다 낫다. 완전한 production 3D 쇼케이스는 아니지만, Phase 1의 기반만으로도 AS-IS보다 확실히 개선된다.
